- 26.11 разобран разрыв на Android 14 — это была настоящая ошибка: окно «Разрешить ИИ?» было отдельной Activity, и Android 14 блокировал её запуск из службы, пока на экране чужое приложение (`BAL_BLOCK` в logcat), человек вопроса не видел. Теперь окно согласия — оверлей службы (`Consent.kt`, TYPE_ACCESSIBILITY_OVERLAY), ConsentActivity удалена.
- Вторая причина сбоев — тестовая: `pm clear` на медленном эмуляторе обрабатывается системой с опозданием до 30 с и выключает службу посреди прогона. В сценарии добавлено `am wait-for-broadcast-idle` и проверка, что служба включена перед подключением.
- Прогон 45764703162 (оверлей с фокусом): A12, A54, Redmi Note 13, S24 Ultra — 23 из 23; S24 и Z Fold6 — 22 из 23 (не прошла «прокрутка»), Pixel 8 — 16 из 17 (не нашёл строку TEST_MAIN после «Отказать»). Окно согласия на Android 14 работает везде.
- Пробовала оверлей без фокуса (45765399234) — хуже, 1 из 8; откатила.
- Контрольный прогон после отката 45766136079: A12, A54, S24, Pixel 8 — 23 из 23; Z Fold6 — 22 из 23 (прокрутка), S24 Ultra — 15 из 17, Redmi Note 13 — 10 из 11 (тест не увидел «Тест-заметки» после разрешения). Сбои плавают между моделями от прогона к прогону — это сценарий и датчик E2E на медленных эмуляторах, а не одна модель.

## Правило 33 (защита от ИИ, 26.11) — план

Pilot сам является ИИ-агентом, поэтому правило применяется так: пилотом нельзя работать с данными владельца и его проектов без личного допуска владельца.

1. Policy: по умолчанию запретить приложения проектов владельца (префиксы `kz.worktime.`, `kz.workdesk.`, Коммит, Академия, Сенім и др.); снимается только ключом допуска.
2. Допуск: свой ключ НЕ заводить — общий признак WorkDesk в консоли (~/projects/workdesk-console, ведёт сессия workdesk-console-db). Релей `/api/pilot/ws`: пользователь по `userByBearer(req)` (src/auth.js, как в src/claude-relay.js handleUpgrade), проверка `aiStatus(user)` (src/tenancy.js) → при !active `rejectUpgrade(socket, 403, 'Forbidden')` с reason (уже про info@worktime.kz). Допуск выдаёт суперадмин (users.ai_allowed, журнал ai_grants). События пилота писать в audit_events с kind='pilot' и сказать workdesk-console-db, чтобы добавил их в /admin/api/ai-events. Клиенту статус — GET /api/workdesk-ai/status.
3. Лимиты в мосте и релее (частота вызовов, снимки в минуту), журнал действий отправлять на модерацию.
4. Условия использования и окно раскрытия в приложении: запрет работы с данными проектов владельца через ИИ без допуска; строка «Допуск: напишите на info@worktime.kz, что и зачем хотите сделать». То же в README.
5. Решено владельцем 26.11 (правила 25, 33): встроенный ИИ продуктов разрешён для данных самого пользователя; WorkDesk AI (и пилот в нём) бесплатно, но только по допуску владельца (заявка на info@worktime.kz). Значит, ключ допуска на релее обязателен для всех, кроме администраторов.

## Правила 26.11 (14, 16, 10, 18)

- Распространение вне Play разрешено (№14). Обновления — со своего сервера с проверкой подписи (№16): исполнитель сверяет подпись APK с сертификатом SHA-256 b50f03c7…f0554a до установки; сделать вместе с уведомлением в WorkDesk AI.
- Тяжёлые сборки, если кончатся лимиты GitHub, — на test.worktime.kz, не на main (№10); `tools/build-on-main.sh` переделать под test.
- ПДн (№18): сервер ПДн не хранит. Журнал действий — только на телефоне (`files/journal`), мост — на ПК пользователя. Снимки экрана и вводимый текст уходят в Claude (США) через Claude Code самого пользователя — это раскрыто в окне согласия. Релей `/api/pilot/ws` ставить на main (РК) и не сохранять содержимое, только журнал допусков.

## Только для телефона или ноутбука

- Проверка на реальных телефонах (One UI, HyperOS): эмулятор не воспроизводит оболочки производителей. Нужен телефон по USB/Wi-Fi с `adb` или ферма реальных устройств.
- Путь «iPhone через Mac»: нужен Mac с iPhone.
- iPhone как исполнитель невозможен (iOS не даёт управлять чужими приложениями).

## Как проверить

- Мост: `cd bridge && npm test`.
- Android: CI собирает и тестирует сам; артефакт `WorkDeskAIPilot-apk`.
- Эмуляторы: Actions → `e2e-emulators` → Run workflow; артефакты `e2e-<API>-<n>` (снимки, `result.json`).
