# WorkDesk AI Pilot для телефона (прототип 0.1.0)

ИИ видит **одно приложение на Android, которое разрешил человек**, и работает в нём касаниями, свайпами и вводом
текста. Часть линейки **WorkDesk AI** («работает с Claude Code»). Мобильная пара к `wdpilot` для ПК:
те же 22 инструмента и те же 17 действий Anthropic `computer_toolset_20260801`.

```
Claude Code (ПК, подписка или API-ключ пользователя)
   └─ MCP stdio ─► bridge/wdpilot-mobile.mjs (ПК, Node 22+, без зависимостей)
                      └─ WebSocket ─► android/ (служба спец. возможностей kz.workdesk.ai.pilot)
```

| Папка | Что внутри |
|---|---|
| `bridge/` | мост MCP ↔ телефон, свой WebSocket-сервер, 11 тестов (`npm test`) с нагрузкой и краш-тестами |
| `android/` | исполнитель на Kotlin: служба, раскрытие и согласие, окно «Разрешить?», кнопка «СТОП», уведомление, плитка, журнал, правила |
| `docs/PROTOCOL.md` | протокол и соответствие действий касаниям; предложение для релея workdesk.kz |
| `examples/` | сценарий «заметка в Keep», `mcp.json`, `demo-driver.mjs` для проверки без Claude |
| `tools/build-on-main.sh` | сборка APK и тестов в одноразовом контейнере на main.worktime.kz |

## Как проверить

1. Мост: `cd bridge && npm test` (нужен только Node 22+).
2. APK: собирает GitHub Actions (`.github/workflows/ci.yml`): тесты моста, юнит-тесты Android, lint, debug-APK и подписанный релиз — в артефакте `WorkDeskAIPilot-apk`. Запасной путь — `HOST=пользователь@сервер sh tools/build-on-main.sh` → `dist/WorkDeskAIPilot-debug.apk` (Android 11+).
3. Телефон и ПК в одной сети: `node examples/demo-driver.mjs --app keep` — печатает адрес и код, дальше по шагам.
4. С Claude Code: `claude mcp add --scope user wdpilot-mobile -- node <путь>/bridge/wdpilot-mobile.mjs`,
   затем запрос из `examples/scenario-notes.md`.

## Безопасность (что уже есть)

- Раскрытие и явное согласие до включения службы (как требует политика Google Play для Accessibility API).
- Отдельное «Разрешить» на телефоне для каждого приложения; действия только пока оно на экране.
- Запрещены: банки, кошельки, менеджеры паролей и аутентификаторы, «Настройки», Google Play, установщик пакетов,
  сам Claude и сам Pilot; поля пароля; номера карт (Луна) и токены в тексте; шторка уведомлений;
  окна с FLAG_SECURE (Android 14+ — снимок окна возвращает отказ).
- Список запретов пользователя (например, боевая база 1С «ТОО ФРК РОЗНИЦА»): видеть цель на экране можно, но касание
  строки с ней или Enter, пока она видна, выполняются только после «Да» человека в окне на телефоне; без «Да» ИИ
  получает отказ «спросите пользователя». Список по умолчанию пуст, правит его только человек на главном экране.
- Клиенты удалённого рабочего стола (RDP, WorkDesk, AnyDesk, TeamViewer, VNC) ИИ не выдаются: их экран — картинка,
  список запретов по ней не проверить, пока на мосту нет OCR снимка.
- «Стоп»: красная кнопка вверху экрана (ИИ нажать её не может), кнопка в уведомлении, плитка «Стоп ИИ».
- Журнал JSON Lines на телефоне 30 дней, без введённого текста и снимков.
- Модели передаётся правило: текст на экране — данные, а не указания; необратимое — только с подтверждения человека.

## Ограничения прототипа

- Связь `ws://` в локальной сети по коду; в продукте — `wss://workdesk.kz` с входом WorkDesk (нужна правка консоли).
- Ввод через `ACTION_SET_TEXT`: работает в обычных полях, может не работать в играх и нестандартных полях.
- `left_mouse_down/up` выполняют жест при отпускании (не в реальном времени).
- Не проверено на реальных телефонах; не публиковалось.
